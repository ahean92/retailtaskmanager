# Серверные проверки

Проверка — `.lsf`-скрипт, который шлётся в `POST /eval/action` под `admin` и отвечает JSON
`ok` / `checks` / `failures` (и, по желанию, `expected`). Стиль — `agent-docs/PATTERNS.md`,
раздел «Автотесты (/eval)».

**Только тестовые стенды.** `/eval` работает, пока у хоста `settings.enableAPI` не равен 0.
На боевом хосте стоит `enableAPI=0`, и там `/eval` закрыт даже для `admin`: ни набор, ни
отдельные проверки на нём не запускаются.

## Регрессионный прогон

Одна команда из корня репозитория:

```bash
powershell -ExecutionPolicy Bypass -File scripts/tests/run-server-suite.ps1
```

- поднимает хост на lsFusion 6.2 на **новой** базе через `run-62-host.ps1` (верхние модули
  `StoreTaskStandalone` и `ExternalApp`), засевает её `suite_seed_62.lsf`, гонит набор,
  останавливает сервер по PID и удаляет базу;
- печатает по строке на проверку и итог «пройдено / упало / ожидаемый отказ»;
- код возврата 0 — ничего не упало, 1 — упала проверка, не поднялся сервер или не прошла уборка.
  При неуспехе логи сервера остаются в рабочей папке, путь выводится последней строкой.

Параметры: `-DbName` (имя новой базы, по умолчанию `zzz_suite_<время>`),
`-HttpPort`/`-RmiPort`/`-WsPort`/`-DebugPort` (по умолчанию 7701/7702/8909/1419),
`-Only имя,имя` — часть набора, `-KeepRunning` — оставить сервер для разбора (в конце выводятся
`WorkDir`, `PID`, `Base`; остановка — `run-62-host.ps1 -Stop -WorkDir <папка>`). С `-KeepRunning`
вывод не передавать в конвейер (`| tail` и т. п.): сервер наследует дескрипторы вывода, и
конвейер ждёт его остановки.

Против уже поднятого сервера, например стенда на `master`:

```bash
powershell -ExecutionPolicy Bypass -File scripts/tests/run-server-suite.ps1 -Base http://192.168.42.28:8888
```

Тогда проверки, написанные под свою базу 6.2 (столбец «Хост» ниже), пропускаются.

**Ожидаемый отказ.** Проверка может вернуть ключ `expected` — текст известного, ещё не
исправленного дефекта, который она воспроизвела. Такая проверка не считается упавшей. Текст
описывает, что не так у пользователя; когда дефект исправят, ветку `expected` в проверке
заменяют обычной сверкой.

демо-стенд.

### Свой хост, отдельной командой

| Проверка | Запуск | Почему не в наборе |
|---|---|---|
| `run-62-host.ps1 -Check host62_check.lsf` | сам поднимает хост | сценарии, видные только на 6.2 |
| `run-core-only-host.ps1` | сам поднимает хост `hosts/CoreOnlyHost.lsf` | проверяет сам старт ядра без пакетов |
| `ticket37494_check` | `run-archived-host.ps1` (`hosts/ArchivedHost.lsf`) | нужен шов архива объекта хоста |
| `ticket37494_batch_check` | `run-batch-host.ps1` (`hosts/BatchHost.lsf`) | хост без пакета AI |
| `check36839-fresh-db.ps1` + `ticket36839_rights.lsf` | сам поднимает сервер | права и график на первом старте базы |
| `check37345-fresh-db.ps1` | сам поднимает сервер трижды | регламенты между перезапусками |

Обёртки `run-core-only-host`, `run-archived-host`, `run-batch-host` собирают classpath через
`mvn`; на машине без Maven они не работают.

### Под стенд с демо-данными

Ходят в ручки под учётками демо-стенда (`demo.user1`, `sosedi.tech1` и т. п.) и заводят
синтетику ZZZ через `/eval`: `check37157.ps1`, `check37179.ps1`, `check37342.ps1`
(+ `ticket37342_check.lsf`), `check37346.ps1`, `check37349.ps1`, `check36839.py`,
`check36839-it4.py`. Под mite-хост: `ticket37046_mite_check`, `ticket37047_version_check`.
Под erp-стенд: `fb36781_erp_check`, `workflow_check`.

### Диагностика данных стенда

Только читают и печатают состояние базы, без вердикта: `exec_duplicates_check`,
`notification_thread_check`, `ticket37046_check`, `ticket36835_check` (после сида
`scripts/demo/ticket36835_demo.lsf`), `ticket37192_check` (нужны сиды `scripts/demo`).

## Обёртки одной проверки

`run-scoring-check.ps1`, `run-sections-check.ps1`, `run-export-check.ps1`,
`run-ai-draft-check.ps1` шлют одну проверку на указанный стенд (`-Base`). То же на своей базе
6.2 — `run-server-suite.ps1 -Only <имя>`.

## Грабли 6.2, найденные набором

- `GROUP MAX Класс x` без условия падает при компиляции запроса (NullPointerException);
  писать `GROUP MAX Класс x IF x IS Класс`.
- Одна группа по нескольким независимым ключам через `OR` — «операция над множеством
  некорректна»; считать по группе на ключ и складывать.
- Отметка `DATA LOCAL`, поставленная до `APPLY NESTED LOCAL`, констрейнтом не видна; ставить её
  внутри `APPLY { … }`, как это делают сами действия (`doReturn`).
