# Пульс — Задачи (Flutter MVP)

Мобильный клиент подсистемы **StoreTask** (задачи для магазинов). Offline-first:
список задач и смена статуса работают без связи, изменения ставятся в очередь и
синхронизируются автоматически при появлении сети.

## Что умеет MVP

- Загрузка списка открытых задач из lsFusion (`/exec/StoreTask.apiTasks`).
- Кэш в локальной SQLite — список читается мгновенно и **работает офлайн**.
- Карточка задачи: объект, тип, детали, срок, приоритет, исполнитель.
- Смена статуса задачи. Офлайн изменения пишутся в **outbox** и синхронизируются
  (`/exec/StoreTask.apiSetStatus`) при восстановлении связи или вручную.
- **Заполнение чек-листа** (задачи типа `checklist`): пошагово по разделам, крупные
  кнопки вариантов / числовой ввод + комментарий при несоответствии, бегущая оценка и
  вердикт (считается локально — работает офлайн), завершение с серверной проверкой.
  Ответы кэшируются и синхронизируются через отдельную очередь. Фото — следующим шагом.
- Экран подключения: адрес сервера, логин/пароль (HTTP Basic), фильтр по исполнителю.

## Требования

- Flutter SDK **≥ 3.16** (проверено на 3.44.7, Dart 3.12). Проверить: `flutter --version`.
- Для сборки APK — Android SDK с `cmdline-tools` и принятыми лицензиями
  (`flutter doctor` / `flutter doctor --android-licenses`), либо Android Studio.
- Устройство Android/iOS или эмулятор.
- Запущенный сервер lsFusion с модулем `StoreTaskApi` (см. ниже).

## Сборка и запуск

Платформенные папки (`android/`, `ios/`) уже сгенерированы и лежат в репозитории —
`flutter create` запускать не нужно. В каталоге проекта:

```bash
cd mobile/pulse_tasks
flutter pub get
flutter run              # на подключённое устройство/эмулятор
# либо собрать APK:
flutter build apk --release
```

Готовый APK окажется в `build/app/outputs/flutter-apk/app-release.apk`.

Cleartext HTTP (для dev-сервера по `http://…:9080`) уже разрешён в
`android/app/src/main/AndroidManifest.xml` (`usesCleartextTraffic="true"`).
В проде за HTTPS этот атрибут можно убрать.

### Адрес сервера в приложении

- Реальное устройство в одной сети: `http://<IP-компьютера>:9080`
- **Эмулятор Android**: хост-машина видна как `http://10.0.2.2:9080`
- **Симулятор iOS**: `http://localhost:9080`

Логин/пароль можно оставить пустыми, если `/exec` открыт анонимно (как на dev-сервере;
вход по умолчанию — `admin` с пустым паролем). Кнопка «Проверить подключение»
дёргает `apiStatuses` и показывает результат.

## Серверная часть (lsFusion)

Модуль: [`src/main/lsfusion/storeTasks/api/StoreTaskApi.lsf`](../../src/main/lsfusion/storeTasks/api/StoreTaskApi.lsf),
подключён в `StoreTask.lsf`. Три эндпоинта (`@@api`, отдаются на web-порту):

| Метод | URL | Назначение |
|-------|-----|-----------|
| GET | `/exec/StoreTask.apiTasks` | Список открытых задач (JSON-массив) |
| GET | `/exec/StoreTask.apiStatuses` | Справочник статусов |
| POST | `/exec/StoreTask.apiSetStatus?id=<taskId>&statusId=<code>` | Смена статуса |

Пример элемента `apiTasks` (null-поля опускаются):

```json
{"id":"ST000001","object":"Магазин №1 (Тверская)","address":"ул. Тверская, 10",
 "type":"Проверка по чек-листу","typeId":"checklist","status":"В процессе",
 "statusId":"in progress","deadline":"2026-07-25","subtitle":"Открытие магазина"}
```

`apiTasks` намеренно **без параметров**: на сервере 7.0 `/exec` для параметризованного
`@@api`-экспорта возвращает пустое тело, если строковый параметр опущен/пуст. Поэтому
эндпоинт отдаёт все открытые задачи, а фильтр по исполнителю применяется на клиенте
(в выгрузке есть `assigneeId`).

Засеять демо-данные на сервере (8 задач в разных статусах):

```bash
curl "http://localhost:9080/eval/action" --data-urlencode "script=StoreTask.generateTestData();"
```

## Архитектура клиента

```
lib/
  models/        task.dart, task_status.dart          — модели + (de)сериализация
  data/
    settings.dart          — настройки подключения (shared_preferences)
    api_client.dart        — HTTP-клиент над /exec/StoreTask.*
    local_db.dart          — SQLite: tasks, statuses, outbox
    task_repository.dart    — offline-first: кэш + outbox + синхронизация (ChangeNotifier)
  ui/            settings_screen, task_list_screen, task_detail_screen, widgets/task_card
  main.dart
```

**Поток данных.** Чтения всегда идут из локальной БД (мгновенно, офлайн). `refresh()`
тянет с сервера и перезаписывает кэш. Смена статуса → запись в `outbox` (эффективный
статус задачи берётся из outbox, пока не подтверждён сервером) → попытка `syncOutbox()`.
При обрыве связи очередь сохраняется и досинхронизируется при реконнекте
(`connectivity_plus`) или по кнопке синхронизации в шапке списка.

## Ограничения MVP / что дальше

- Пароль хранится в `shared_preferences` в открытом виде — для прода заменить на
  `flutter_secure_storage`.
- `apiSetStatus` при ошибке (например, статус недопустим для типа задачи) возвращает
  HTTP 500; сейчас запись остаётся в очереди, ошибка показывается пользователю.
  Для прода стоит отделять постоянные ошибки от временных сетевых.
- Выполнение задач (заполнение чек-листа/пересчёта/ценников) в приложении не
  реализовано — только просмотр и смена статуса (см. роадмап `docs/mvp/roadmap.md`, п.14).
