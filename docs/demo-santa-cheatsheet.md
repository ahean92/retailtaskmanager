## 2. Сценарии (пять из ТЗ)

### 1) Чек-листы + план на ноябрь
- Шаблон **«Чек-лист «РЫБА» (100 баллов)»**: 8 балльных разделов, 40 критериев,
  шкала 95–100 отлично / 85–94 хорошо / 70–84 удовл. / 60–69 плохо / <60 очень плохо —
  в точности Excel Санты («92 чек лист 28.07.2026.xlsx»).
- Показать: `SANTA-FRESH` — закрытая сегодня проверка С - 224 (100 баллов → «Отлично»),
  `ST000036` — «в работе» с частичным бланком; незакрытые замечания создают
  **корректирующие**: `ST000028…32` «Устранить: …» (привязаны к пунктам чек-листа).
- **Ноябрь запланирован**: 2 правила графика — «РЫБА ежемесячно, Санта 400» (121 магазин)
  и «…, Санта 600» (50) → **171 задача**, сроки разнесены равномерно по дням месяца
  (5–6 проверок в день); Уручьё: С - 216 — **6 ноября**, С - 272 — **12 ноября**
  (`ST000237` → Гончарук, `ST000359` → Лисица).
  Экран: *Операции → График проверок* — календарь (диапазон дат в шапке переключить
  на ноябрь: 01.11–30.11.2026), карточка правила с прогнозом и журналом.
  Календарь по умолчанию открывается на текущем месяце — на ноябрь смотрим
  осознанно, это часть рассказа («запланировали на месяц вперёд»).
  Разнос сроков — скрипт 10; после генерации следующего месяца прогнать его ещё раз.

## 4. Рекомендуемый ход (≈15 мин, веб + телефон)

1. **Веб, `sup.demo`** — сводка супервайзера: просрочки и несоответствия сети, средний балл. → список задач, фильтр «Проверки».
2. **Веб, `zav216` или admin** — `SANTA-T1`: пересчёт с расхождением (чипсы 18/15). → `ST000042`/`SANTA-T2`: ценники, подсветка колонок.
3. **График проверок** — календарь ноября: жёлтые клетки, правило «РЫБА ежемесячно», уручьёвские задачи с исполнителями; журнал правила.
4. **Заявки из внешних систем** — BTRX-2001/2002 → задачи заведующим; разбор карантина BTRX-2099 (сопоставить площадку «99» и создать задачу).
5. **Веб, `it.eng`** — очередь ИТ: SANTA-IT1/IT2 на весы; *Оборудование → Загрузка прайса в весы*: две красные транзакции + зелёная.
6. **Телефон, `zav216`** — главная по гео (продажи с отклонением), 🧹 «Уборка мусора» → фотоотчёт; (опционально) 🔍 «Внезапная проверка».
7. **Финал (веб, admin)** — отчёты: свод нарушений по сети, корректирующие `ST000028…32` с перепроверкой устранения; экспорт выполнения в PDF/HTML из карточки.

## 5. Неприятности и запасные ходы

- **Пустой экран веб-клиента** после рестарта сервера — перезапустить Tomcat стенда
  (он держит RMI-заглушки старого инстанса и рисует пустоту).
- **Телефон не видит сервер** — одна Wi-Fi сеть с машиной стенда; проверить:
  `curl -u zav216:zav216 "http://192.168.42.22:7651/exec/StoreTask.apiTasks"`.
- **Сброс данных** — скрипты идемпотентны, прогон 01→10 восстанавливает всё
  (05 пересоздаёт правила графика и ноябрь, 10 разноносит сроки по месяцу,
  09 — свежая закрытая проверка).
- **Карантин уже разобран** (BTRX-2099 создал задачу) — для повторного показа
  прогнать 03: новая карантинная заявка заводится только если её нет; создать
  ещё одну с новым sourceId можно копированием блока в скрипте.
- **Не трогать**: канал `hypothesis` (8 правил, ~24 заявки — служебные), пользователя
  `KME` (реальный тех.служащий стенда), чужие подразделения U-RET/U-AUDIT/U-S*.
