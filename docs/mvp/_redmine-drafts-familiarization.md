## Тема

**[#37497](http://support.luxsoft.by/issues/37497) [Бланк] Ознакомление сотрудника
с результатом проверки: пункт-выбор сотрудника, уведомление и доступ к результату** — оценка S–M.

## Постановка (как в Redmine)

**Цель.** Проверяющий прогоняет чек-лист на магазине; в бланке есть пункт «Ознакомил
с результатами» с выбором сотрудника из этого магазина; выбранному сотруднику приходит
уведомление, он может просмотреть результат проверки и высказать своё мнение
в комментариях задачи. Собрать сценарий из готовых механизмов с минимальными доработками.

**Переиспользуется без изменений:**

- канал справочника `employee` (#36841, `fillable/RefPerformer.lsf`): поле `objectref`
  с каналом `employee` — выбор сотрудника по ФИО; кандидатов отдаёт `apiRowSubjects`;
- наблюдатели (#37135/#37136, `task/TaskWatcher.lsf`): `watcher → participant` — задача
  в выдаче `apiTasks`, группа «Наблюдаю» на телефоне: просмотр результата и переписка
  доступны, работа по задаче — нет; дальнейшие события через `notifyWatchers`;
- точка завершения проверки: событие по `SETCHANGED(state(Filling)) AND finished AND
  resultRecorded` — образец `notification/NotificationFill.lsf`.

**Часть 1. Фильтр сотрудников по магазину.** Шов `available(RefValue, CheckObject)`
(`fillable/RefValue.lsf`) для канала сотрудников не реализован — ручка отдаёт весь канал.
Для erp-хоста — реализация в мосту `StoreTaskPerformerErp` (сотрудники, привязанные
к объекту); в standalone данных о принадлежности нет — остаётся весь список.
Удобство выбора, не безопасность: `all=1` по-прежнему весь канал.

**Часть 2. Уведомление ознакомленному.** Новый модуль по образцу `NotificationFill`:

- флаг на поле шаблона (`DATA BOOLEAN` на `Field` + строка в форму шаблона) — им
  опознаём «тот самый» пункт; конвенция «все employee-поля уведомляют» превратила бы
  любой пункт с ФИО в рассылку;
- событие `familiarized` «Ознакомлен с результатом» + title/body по образцу соседних;
- триггер — тот же, что у «Проверка завершена» (после `resultRecorded`); адресаты —
  `refValue(Filling, f)` полей шаблона с флагом (значение канала — `TaskPerformer`);
- адресату: `watcher(задача, p) <- TRUE` (участник → «Наблюдаю» → результат
  и переписка) и `notify` стартовым событием.

Открытый вопрос при постановке в работу: подписка сегодня — решение человека
(«Следить»); здесь строку пишет система. Снятие «Не следить» остаётся за сотрудником;
повторная проверка подписку не дублирует.

**Готово когда:**

1. Пункт «Ознакомил с результатами» настраивается в шаблоне (objectref + канал employee
   + флаг уведомления); на телефоне сотрудник выбирается из списка.
2. После завершения проверки выбранный сотрудник получает уведомление; задача появляется
   у него в «Наблюдаю»; результат доступен; мнение — в комментариях задачи, ответы
   доходят проверяющему.
3. Сотрудник не может работать по задаче (заполнять, брать, менять статус) — только
   смотреть и переписываться.
4. Мобильный клиент не меняется.
