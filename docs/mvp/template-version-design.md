# Новая редакция чек-листа

Задача «новая редакция чек-листа» (#37174). Продолжение двух предыдущих:
[`filling-result-freeze-design.md`](filling-result-freeze-design.md) закрыл ПЕРЕСЧЁТ (правка
веса или порога прошлое больше не двигает), [`template-clone-design.md`](template-clone-design.md)
— УДАЛЕНИЕ (поле с ответами не убрать, зато есть клон). Здесь — СВЯЗЬ: клон, которым правят
состав чек-листа, перестаёт быть чужим шаблоном и становится следующей редакцией прежнего.

## Что было сломано

Клон (#36985) начинается с нуля, и всё, что привязано к объекту шаблона, обрывается:

| Что | Как ломалось |
|---|---|
| сравнение с прошлым разом (#36778) | `prevFilling` искал тот же шаблон — у первой проверки по клону прошлой нет |
| корректирующие | перепроверка искала ту же пару «шаблон + поле»: заведённую по старому клон не снимет никогда, а на то же нарушение заведёт дубль |
| свод баллов | фильтр по шаблону — один клон, одна выборка; история по чек-листу рвётся |
| свод нарушений | строка на объект поля: один вопрос в двух шаблонах — две строки |
| пресеты и график | ссылаются на объект шаблона, переводятся руками |

## Модель

**Редакция — это шаблон.** Не версия внутри шаблона, не слепок структуры: отдельный
`Template` со своими разделами, полями и колонками. Поэтому бланк, подсчёт, печать и ручки
заполнения не правились вовсе — структура редакции заморожена самим фактом, что это
отдельный объект, и заполнение с задачей ссылаются на конкретную редакцию, как и раньше.

Новое — три поля в `fillable/Template.lsf`:

```lsf
family = DATA Template (Template);        // первая редакция семейства; у одиночного — он сам
version 'Версия' = DATA INTEGER (Template);
previousVersion = DATA Template (Template);
draft 'Черновик' = DATA BOOLEAN (Template);
published (Template t) = t IS Template AND NOT archived(t) AND NOT draft(t);
```

Состояния — черновик → опубликована → снята — считаются из двух флагов, отдельного
справочника состояний нет: `archived` уже был (#36985), `draft` добавлен, а «опубликована» —
это «ни то, ни другое».

**Семейство ссылкой на объект, а не по коду.** «Тот же чек-лист» спрашивают три места сразу
(прошлая проверка, перепроверка корректирующей, своды), и сравнение объектов дёшево. По коду
не вышло бы: шаблонов без кода в базе большинство — код появился позже них, — и они все
слиплись бы в одно семейство с ключом `NULL`. Цепочку `previousVersion` для этого пришлось бы
разворачивать транзитивно, поэтому она осталась справочной: семейство держит `family`.

**Умолчания и миграция — одно и то же.** `WHEN LOCAL SET(Template t IS Template)` ставит
новому шаблону `version = 1` и `family = t`, а `onStarted` доливает то же существующим. Каждый
сегодняшний шаблон — первая и единственная редакция сам себе, поэтому `migration.script` не
нужен: ни одно имя не переименовано, ни одна `DATA` не переехала.

### Уникальность и лукапы

Четыре `GROUP AGGR` — каждый одновременно и поиск, и ограничение:

```lsf
publishedVersion = GROUP AGGR Template v WHERE published(v) BY family(v);   // одна опубликованная в семействе
draftVersion     = GROUP AGGR Template v WHERE draft(v)     BY family(v);   // и один черновик
template         = GROUP AGGR Template t WHERE published(t) BY code(t);     // поиск по коду
templateVersion  = GROUP AGGR Template t BY code(t), version(t);            // поиск по коду и номеру
```

**Имя `template(code)` не менялось — изменился ответ.** Раньше он отдавал шаблон с таким
кодом, теперь — опубликованную редакцию семейства. Поэтому все, кто ходит по коду
(`apiCreateTask`, `apiTemplates`, `AiDraftDecision`, `AiTools`), получили текущую редакцию без
единой правки, а снятые редакции и черновики кодом просто не адресуются.

**Код — имя семейства.** Он общий у всех редакций (`CONSTRAINT code(t) != code(family(t))`),
правится только на первой (в карточке остальных `READONLYIF version(t) > 1`). Без кода
редакцию не сделать: сначала код — иначе телефон и AI не найдут чек-лист.

### «Тот же вопрос в другой редакции» — `Field.familyField`

Клон сохраняет коды полей (решение #36985: код поля — ключ очередей мобильного клиента), и
поле уникально по шаблону и коду. Значит вопрос — это пара «семейство + код поля». Пара
сведена к одному объекту:

```lsf
familyField 'Пункт' (Field f) = (OVERRIDE
    (GROUP MIN Field g IF family(template(g)) = family(template(f)) AND code(g) = code(f)),
    f) MATERIALIZED;
```

Представитель — поле самой ранней редакции, где этот код появился. Ранней, а не последней,
именно ради стабильности: опубликованная редакция больше не меняется, значит представитель
никуда не переезжает — ни при публикации следующей, ни, что важнее, пока следующую правят
черновиком. `OVERRIDE` на само поле — для полей без кода: без запасного варианта они выпали бы
из группировки целиком, а не встали каждое своей строкой.

Сравнение объектов вместо сравнения пары строк — то, ради чего это заведено: `familyField(a) =
familyField(b)` работает в `GROUP`, в фильтре формы и в индексе, а `family + code` пришлось бы
тащить двумя join'ами в каждое из мест ниже.

## Публикация

Одно действие (`fillable/TemplateVersion.lsf`), одна сессия:

```lsf
publish 'Опубликовать редакцию' (Template n) {
    APPLY; IF canceled() THEN RETURN;          // карточка черновика редактируемая
    NEWSESSION {
        LOCAL prevPublished = Template();
        prevPublished() <- publishedVersion(family(n));
        IF prevPublished() THEN {
            archived(prevPublished()) <- TRUE;
            rebindTemplate(prevPublished(), n);
        }
        draft(n) <- NULL;
        APPLY;
    }
}
```

Порядок внутри сессии значения не имеет: оба ограничения («одна опубликованная», «один
черновик») проверяются на `APPLY`, к которому состояние уже согласовано.

`rebindTemplate` — **шов**, а не список присваиваний, по той же причине, что и швы копирования
шаблона: пресеты живут в мобильном пакете, правила графика — в графике, ядро про них знать не
должно.

| Кто реализует | Что перевешивает |
|---|---|
| `mobile/QuickAction.lsf` | `template(QuickAction)` — пресет телефона |
| `schedule/SchedulePlan.lsf` | `template(SchedulePlan)` — правило графика |

`ai/AiRequest.lsf` намеренно не перевешивается: журнал пишет, по какому шаблону запрос **был**,
и это прошлое.

### Не начатые задачи

Задача хранит шаблон, заполнение берёт его в момент старта (`FormTask.startExecution`), поэтому
созданная, но не начатая задача остаётся на своей редакции — это уже так работает, и менять
это не нужно. Пока заполнения нет, подменить бланк безопасно; у начатой — нет, ответы уже
разложены по полям её редакции.

Форма `versionTasks`: не начатые открытые задачи прежних редакций семейства, колонка-галка
«Перевести», кнопки «Отметить все» / «Снять отметки» / «Перевести отмеченные» и счётчик
отмеченных.

Галка — `DATA LOCAL BOOLEAN (Task)`, а не выделение строк грида (`[ SELECT ]`): выделение
плохо видно в таблице, теряется от одного случайного клика и не даёт снять отметку с одной
строки, не сбив остальные. `LOCAL` потому, что форма открывается своей сессией: отметки
живут только в ней, в базу не едут и очищаются сами при успешном `APPLY` — а при неудачном
форма остаётся ровно такой, какой её отдали пользователю. Перевод идёт присваиванием по
множеству (`template(Task t) <- n WHERE selected(t) AND movable(n, t)`), `movable` в условии —
страховка на случай, если задачу успели начать, пока форма была открыта.

## Что перешло на семейство

| Место | Было | Стало |
|---|---|---|
| `Filling.prevFilling` | `template(p) = template(f)` | `family(template(p)) = family(template(f))` |
| пометка «в прошлый раз замечание» (`FillReadApi`) | тот же объект поля | `prevNonconformity` — поле прошлой проверки по КОДУ |
| `CorrectiveRecheck.recheckFilling` | тот же шаблон и то же поле | семейство + `recheckField` по коду |
| `Corrective.pendingCorrective` | `sourceField(t) = f` | `familyField(sourceField(t)) = familyField(f)` |
| `ColumnCalc.prevRow` / `consumption` | тот же объект поля и колонки | `familyField` у поля, код у колонки |
| `ScorecardReport.matchTemplate` | `template(e) = filterTemplate()` | семейство + отметка `mixedVersion` |
| `NonconformityReport` — строка свода | объект поля | `familyField`, в гриде только представители |

**Свод баллов.** Фильтр по шаблону выбирает семейство: свод за полгода обязан складывать
проверки по чек-листу, а не по одной его редакции. Проценты редакций с разным составом
сравнимы условно — убрали пункт, и оставшиеся стали весить больше, — поэтому строка, где в
периоде были проверки разных редакций, помечается (`mixedVersion`), а не тихо усредняется.

**Свод нарушений.** Строка — пункт семейства; в гриде только представители
(`FILTERS familyField(f) = f`), а считают они по всем редакциям сразу через `sameField(e, f)`
(«то же поле в шаблоне этой проверки»). Показывается всё из ПОСЛЕДНЕЙ неотложенной редакции
(`lastField`): переименование пункта или раздела — исправление формулировки, и свод должен
показывать нынешнюю. Черновик из выборки исключён: его правки не должны шевелить отчёт до
публикации. Раздел в фильтре сравнивается по названию — у каждой редакции свои объекты
разделов, а называются они одинаково.

Матрица снятых баллов (`deductScore` по колонкам-полям) осталась **по одной редакции**: это
разбор конкретного бланка, и складывать колонки разных составов в одну таблицу нечего.

## Телефон: офлайн-создание

Телефон создаёт задачу офлайн по бланку из кэша `apiTemplates` и присылает только код. Если
между загрузкой кэша и синхронизацией вышла новая редакция, сервер создал бы задачу по новой,
а ответы были бы по старой: убранные поля потерялись бы, варианты из другого набора отверг бы
констрейнт.

- `apiTemplates` отдаёт `version` и фильтрует `published(t)` — черновик телефону не виден;
- `apiCreateTask` принимает `templateVersion`: с номером — именно эта редакция, **даже
  снятая**; без номера — текущая, как и было.

Последнее и есть совместимость: клиенты, которые номер ещё не шлют, продолжают работать без
доработки. Телефонная часть — #37175.

Телефон (#37175) держит номер в кэше шаблона (`PresetTemplate.version`) и кладёт его в тело
`apiCreateTask` рядом с `templateId` только тогда, когда бланк засеян из кэша и заполняется
сразу, — внезапная проверка. Номер фиксируется в теле очереди в момент создания, а не при
отправке: к отправке кэш уже может приехать новой редакцией. Поручение из AI-черновика и
задача, чей шаблон ещё не приехал, номер не шлют — их заполнят потом, по текущей редакции.
Нет номера в `apiTemplates` (сервер без редакций) — нет его и в создании.

## Черновик не виден снаружи

Четыре места, и все четыре — уже существовавшие механизмы, которым поменяли условие:

- **форма `templates`** — она же диалог выбора шаблона (в задаче, в правиле графика, в фильтре
  сводов). Фильтр по умолчанию: `published(t)`; черновики и архив открываются явно (`F6`, `F7`);
- **`SchedulePlan.fireable` и `generateForRule`** — `published(template(p))` вместо `active`;
- **`apiTemplates`, `apiAiSearchTemplates`, `AiTools.matchTemplate`** — `published(t)` вместо
  `active(t)`;
- **`template(code)`** — сам по себе отдаёт только опубликованную.

Жёсткого запрета поставить черновик в задачу по-прежнему нет — по тому же разбору, по которому
его нет у архива (#36985): `CONSTRAINT` на `template(Task)` ломал бы приём заявок отказом
`APPLY` там, где сейчас деградация мягкая.

## Запрет удаления первой редакции

В `TemplateGuard` добавлен седьмой запрет: удалить редакцию, на которой держится семейство,
нельзя, пока есть следующие — иначе чек-лист тихо разорвался бы на несвязанные шаблоны.
Схема та же, что у остальных шести: `PREV` по значению, но текущая проверка объекта
(`v IS Template`), так что удаление всего семейства разом (демо- и тест-скрипты) остаётся
законным.

## Проверка

Руками на стенде (никогда не на боевой БД, см. `_handoff.md`). Автотеста нет намеренно: в
составе задачи его не было.

**Черновик.** Справочники → Шаблоны → опубликованный чек-лист с кодом → «Создать следующую
редакцию». Открывается карточка: имя и код прежние, номер на единицу больше, состояние
«Черновик», код только для чтения. В списке шаблонов он виден только фильтром «Черновики».
В нём удаляется отвеченное поле и меняется тип (запреты #37172 не срабатывают — данных нет).
Второй раз «Создать следующую редакцию» по тому же семейству — отказ.

**Невидимость черновика.** Создание задачи: черновик не предлагается в выборе шаблона.
Правило графика на черновике: «Готов к запуску» гаснет, ручной запуск говорит почему.
`apiTemplates` черновика не содержит. AI по названию черновик не находит.

**Публикация.** «Опубликовать редакцию» → черновик стал текущим, прежняя редакция — «Снята»,
пресет телефона и правило графика показывают новую. `GET apiTemplates` отдаёт новую с её
номером. Задача, созданная после публикации, — на новой редакции.

**Не начатые задачи.** До публикации создать две задачи по старой редакции, одну начать.
После публикации → «Не начатые задачи»: в списке только не начатая. Отметить, перевести —
переехала; начатая осталась на своей редакции и открывается прежним бланком.

**Прошлая проверка.** Провести проверку по старой редакции, опубликовать новую, провести
вторую по тому же объекту: в бланке телефона стоит пометка «в прошлый раз замечание» по
пунктам с тем же кодом; у поля, добавленного в новой редакции, пометки нет; `apiExecutionInfo`
отдаёт `prevDate` / `prevPercent` / `prevRemarks`.

**Корректирующие.** Замечание по старой редакции → корректирующая. Проверка по новой редакции,
тот же пункт отвечен без нарушения → корректирующая снялась. Тот же пункт с нарушением, пока
первая открыта → дубль не завёлся.

**Своды.** Свод баллов по шаблону: проверки обеих редакций в одной выборке, у объекта с
проверками по обеим — отметка «Смена редакции». Свод нарушений: общий пункт одной строкой,
счётчики сложились, название — из новой редакции; пункт, убранный в новой, остался со своей
исторической статистикой.

**Уборка.** Прогнать `scripts/tests/run-scoring-check.ps1`: он сносит задачи и шаблон одной
сессией — проверка, что новый запрет удаления не мешает уборке.

**За чем посмотреть.** Счётчики свода нарушений стали считать через `sameField` — вложенный
`GROUP MAX` по полям внутри `GROUP SUM` по заполнениям. `familyField` ради этого
`MATERIALIZED`, и таблица полей мала (сотни строк), но на боевом объёме заполнений свод стоит
открыть с секундомером. Если окажется медленно, следующий шаг — материализовать `sameField`
или свернуть его в `MATERIALIZED`-свойство `(Filling, Field)`.

**После выкатки** один раз прогнать пересчёт материализаций: `prevFilling` сменил определение
(значения не меняются — у существующих шаблонов `family(t) = t`), а `Field.familyField` новое.

## Осталось за рамками

- **Сравнение редакций в интерфейсе** («что поменялось») — явно не в этой задаче.
- **Автоматический перевод не начатых задач** — только вручную, выбранные.
- **Версии наборов вариантов и шкал оценок.** Это общие справочники: прошлое их правками после
  #37172 не меняется, а новые проверки по всем шаблонам берут текущие.
- **Телефонная часть** офлайн-создания с номером редакции — #37175. Сервер готов и совместим
  со старыми клиентами.
- **Перенумерация редакций** и удаление редакции из середины семейства не предусмотрены:
  номер выдаётся как максимум по семейству плюс один.
