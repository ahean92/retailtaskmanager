# Черновик задачи: просмотр результата выполненной задачи на мобильном

> Подготовлено и **заведено в Redmine 2026-10-20** —
> [#37622](http://support.luxsoft.by/issues/37622), исполнитель не назначен.
> Постановка пришла от пользователя устно («в выполненных задачах на телефоне —
> просмотр результата, без изменения»); серверная часть по решению пользователя в
> объём не вошла (см. «Что осталось за кадром»).
>
> Реализация готова в ветке v6 (не закоммичена на момент заведения).

## [Мобильный] Просмотр результата выполненной задачи (только чтение) — ЗАВЕДЕНО #37622

**Цель.**

В архиве «Выполненные» исполнитель открывает закрытую задачу, но увидеть сданный
результат с телефона нечем: кнопка «Результат» существует только в сценарии
приёмки (у задачи «На приёмке»), а у архивной карточки нет ни главного, ни
второстепенных действий. Просмотрщик при этом уже готов: `PastCheckScreen.forResult`
(бланк с ответами, фото и итогом) и `TaskResultScreen` (фотоотчёт «было/стало» с
комментарием) ничего не редактируют и работают офлайн через кэш. Нужен вход в них
с карточки закрытой задачи.

**Состав.**

* Главное действие «Результат» на карточке архивной задачи (`_primaryAction`
  в `task_detail_screen.dart`): открытие существующего маршрута `taskResultRoute`
  — бланк → `PastCheckScreen.forResult`, фотоотчёт → `TaskResultScreen`.
* Кнопка показывается любой закрытой задаче (Выполнено/Отменено), у которой есть
  хоть одно выполнение (`apiTasks` отдаёт вложение `executions` и для архива);
  где смотреть нечего — кнопки нет.
* Автору и наблюдателю кнопка не показывается: сервер чтение результата им не
  отдаёт (`canView` — исполнитель и принимающий), у них на карточке блок
  выполнений.
* Попутный фикс: закрытые строки собирались в `TaskView` без флагов участия
  (`authoredOnly`/`watchedOnly`/`reviewingOnly` всегда false в архиве) — из-за
  этого автор видел бы кнопку, ведущую в отказ сервера; флаги пробрасываются из
  `Task`, как у рабочего списка (`task_repository.dart`).

**Готово когда.**

В архиве «Выполненные» у закрытой задачи с бланком есть кнопка «Результат»,
открывающая сданный бланк целиком — разделы, ответы, фото, итог/вердикт — без
возможности что-либо изменить. У фотоотчётных задач — экран «было/стало» с
комментарием исполнителя. У отменённой до начала работы задачи кнопки нет.

**Проверка.**

`flutter analyze`; полный набор `flutter test` (536). Сценарии в
`test/completed_tasks_test.dart`: кнопка открывает просмотр и читает собственное
заполнение задачи (`apiExecutionInfo` с `id`, без `prev`); автору кнопка не
положена. Ручная проверка на стенде с телефоном.

**Оценка.** S (реализация — три файла клиента).

## Что осталось за кадром (отдельное решение пользователя)

Пишущие ручки бланка (`apiSetField`, `apiSetCell`, `apiAddRow`/`apiDeleteRow`,
`apiSetFieldPhoto`/`apiDeleteFieldPhoto`, `apiSetResolution`) проверяют только
доступ и существование заполнения (`requireFilling`), но не завершённость —
ответы сданного бланка можно изменить через API. У простого выполнения такой
гвард есть (`Execution already finished` в `SimpleApi`), у бланка — нет.
Пользователь решил серверную часть в этой задаче не трогать; при закрытии дыры —
отдельный тикет (план разбора есть в сессии от 2026-10-20: гвард
`requireUnfinishedFilling` в `FillApiCommon`, семь мутаций; `apiFinishExecution`
остаётся идемпотентным для ретрая очереди, `apiStartExecution` — со своей веткой
`restartable`).
