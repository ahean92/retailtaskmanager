## 2. Что сделано в этой сессии (2026-08-03)

1. **Поднят сервер** для мобильного приложения (val-БД, web 9080) — см. §3. Прогнаны

   концептуально живёт в MITE; в «Пульс» приходит то, что требует человека на месте:
   плановое ТО, отработка аварии по отклонению температуры, поверка весов, обход
   с журналом температур.
3. **Найден дефект движка** (не чинил — вынесено в отдельную задачу): в
   `fillable/Filling.lsf` свойство `nonconformity` помечает несоответствием **любое**
   заполненное number-поле без заданных норм (`inNorm` = NULL → `NOT NULL` = TRUE);
   односторонние нормы (задана только `minNorm` или только `maxNorm`) по той же причине
   не работают вовсе. Та же форма у `cellInNorm` в `FillRow.lsf`. В демо обошёл — задал
   `writeoff` диапазон 0…1000 кг.

## 7. Грабли (проверено на практике)

**lsFusion / движок:**

- `/eval` и `/eval/action`: имя `task` **неоднозначно** (`ProjectManagement.task[STRING]` vs
  `StoreTask.task[STRING]`) → в скриптах для сервера квалифицировать namespace:
  `StoreTask.task('ST000090')`, `StoreTask.Filling`, `StoreTask.taskType`, `Inventory.name`
  для Location. Иначе `ambiguous name`.
- **EXPORT после APPLY в одном действии → пусто.** Read и mutation держим РАЗДЕЛЬНО (так и
  устроен FillApi).
- `/exec` с **параметризованным** `@@api`-EXPORT возвращает пустое тело, если строковый
  параметр опущен/пуст. Поэтому `apiTasks` сделан без параметров, фильтр по исполнителю — на клиенте.
- Сырой `application/json` НЕ биндится на именованные `@@api`-параметры (→ 500) — только через
  `FILE`-параметр + `IMPORT JSON ... AS FILE TO()`. `application/x-www-form-urlencoded` биндится.
- `loadDefaultData` срабатывает только на свежей БД → типы задач на «старой» БД могут
  отсутствовать; генераторы досоздают их сами (`IF NOT taskType('form') THEN …`). Это костыль,
  закрывается тикетом 1 в roadmap.
- number-поле **без норм** = вечное несоответствие (см. §2.3).
- `name(Location)` — `ISTRING[30]`, NONULL: имена магазинов длиннее 30 символов не влезут.
- 🔴 **Проект реверс-транслейтит голые строковые литералы.** Литерал, совпавший с ключом
  i18n-бандла, при парсинге подменяется переводом: `code(fl) <- 'lines'` сохранил в БД
  **«строк»** (ключ `lines=строк` в `MyCompanyResourceBundle_ru.properties`), и код поля
  стал локале-зависимым. **Не использовать голые словарные английские слова как code/id** —
  проверять `grep -E "^<code>=" MyCompanyResourceBundle.properties` (регистрозависимо,
  переводится только точный lowercase-ключ); при совпадении брать несловарный код
  (так `'lines'` стал `'pricelines'`). Технические литералы правильнее писать как `r'...'`.
- 🔴 **`lsfdev.ps1 restart` возвращает exit 0 и «web up», даже если app-сервер упал на
  старте.** Проверять живой API (`curl .../exec/StoreTask.apiStatuses` → JSON), а не только
  веб-порт; при подозрении смотреть `logs/stderr.log` на `ERROR StartLogger`.
- `name(static-объекта)` даёт ПОЛНОЕ каноническое имя (`StoreTask_FieldType.scale`), а не
  короткий код → у статических enum'ов заводится явное `code (…) = OVERRIDE (…)`.
- `boolValue` — **TBOOLEAN** (не BOOLEAN): иначе «нет» = NULL = «не отвечено».
- Приём картинки из base64: `IMAGEFILE(decode(<base64>, 'base64'))` — паттерн из
  `utils/BarCodeReader.lsf`; extension не нужен.
- Голый `DELETE` в `/eval/action` **без** `NEWSESSION { … APPLY; }` даёт 200, но ничего не
  применяет. Идемпотентные `ensure*`-генераторы **не обновляют** уже созданный шаблон —
  после правки шаблона в коде его нужно удалить и пересоздать.

**UI:**

- CSS-скоуп: корень формы = `[lsfusion-form="NS.formName"]`; `[lsfusion-container=…]` — это
  пункт навигатора, не форма.
- Нативные `.btn` тема держит по цвету — цветные кнопки/плитки только своим HTML в
  CUSTOM-компоненте. `CUSTOM 'htmlText'` в 7.0-SNAPSHOT нет (крашит форму).
- `in` как имя свойства ломает парсер формы (парсится как ключевое слово IN).
- Свойство над двумя object-группами в форме — **голая** форма `PROPERTIES p(i, r)`.

**Инфраструктура:**

- Windows-шелл кодирует кириллицу в query как cp1251 до curl → для тестов слать
  percent-encoded UTF-8 или в теле; для `lsfdev api` — только `-ScriptFile` (UTF-8).
- Redmine API: ключ только заголовком `X-Redmine-API-Key`, никогда в URL. Кириллица из
  PowerShell 5.1 — текст в UTF-8 файл, читать `[System.IO.File]::ReadAllText`, слать `UTF8.GetBytes`.
  Временные файлы с ключом удалять.
