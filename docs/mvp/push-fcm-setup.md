# Пуш через FCM: что завести и включить (#36720)

> Инфраструктурная часть задачи: что заводится руками в чужих консолях и что включается
> в бэк-офисе. Кода тут нет — разбор самого канала в разделе 8
> [notifications-design.md](notifications-design.md), реализация в `PushFcm.lsf`.

Шесть шагов: проект Firebase, два файла из него, ключ сервисного аккаунта в настройки,
включённый канал, регламентное задание и — для iOS — APNs-ключ.

## 1. Проект Firebase

[console.firebase.google.com](https://console.firebase.google.com) → **Создать проект**.
Google Analytics не нужен, его подключение можно пропустить. FCM бесплатен и в платный
тариф (Blaze) не упирается.

## 2. Приложения в проекте

Идентификаторы берутся из репозитория и должны совпасть буква в букву, иначе
`google-services.json` не подойдёт к сборке.

| Платформа | Идентификатор | Откуда он в репозитории |
|---|---|---|
| Android | `com.mycompany.pulse_tasks` | `android/app/build.gradle.kts`, `applicationId` |
| iOS | `com.mycompany.pulseTasks` | `ios/Runner.xcodeproj/project.pbxproj`, `PRODUCT_BUNDLE_IDENTIFIER` |

Обратить внимание: у Android и iOS они **разные** (`pulse_tasks` против `pulseTasks`) —
так вышло из шаблона Flutter, и это нормально. Регистрировать надо оба.

* **Android.** «Добавить приложение → Android», ввести package name, скачать
  `google-services.json`, положить в `mobile/pulse_tasks/android/app/google-services.json`.
  Остальные шаги мастера (правка Gradle, проверка связи) в репозитории уже сделаны.
* **iOS.** «Добавить приложение → iOS», ввести bundle ID, скачать `GoogleService-Info.plist`,
  положить в `mobile/pulse_tasks/ios/Runner/GoogleService-Info.plist`. На маке файл надо
  ещё **добавить в target Runner через Xcode** (перетащить в дерево проекта, галочка
  «Copy items if needed», target Runner) — просто лежащий на диске файл в сборку не попадёт.

Оба файла закрыты `.gitignore` и в репозиторий не кладутся: они принадлежат установке
заказчика, а не продукту. Без них приложение собирается и работает — Gradle напечатает
предупреждение, а пуш просто выключится (`PushService.available`).

Здесь же честно назовём цену: **одна сборка перестаёт обслуживать нескольких заказчиков**.
Оформление приезжает с сервера и на APK не влияет (см. `Branding.lsf`), а вот проект
Firebase вшит в сборку — у каждого заказчика она своя.

## 3. Ключ сервисного аккаунта — то, чем сервер ходит в FCM

Простой серверный ключ (`Authorization: key=...`) Google отключил. Актуальный HTTP v1
требует OAuth2-токена сервисного аккаунта, и сервер получает его сам — но для этого ему
нужен приватный ключ.

«Настройки проекта → **Сервисные аккаунты**» → **Создать закрытый ключ** → скачается JSON
вида `pulse-tasks-4f21-a1b2c3d4e5f6.json`.

Этот файл — **настоящий секрет**: кто им владеет, тот шлёт уведомления от имени
заказчика. В репозиторий он не кладётся никогда. Загружается один раз в бэк-офисе:

> **Управление персоналом → Настройка → Настройки → вкладка «Уведомления» → «Пуш
> (Firebase Cloud Messaging)»**, поле «Ключ сервисного аккаунта (JSON)».

Идентификатор проекта, почту сервисного аккаунта и адрес выдачи токена сервер берёт из
самого ключа — перепечатывать их руками не нужно и негде. Рядом кнопка **«Проверить связь
с Firebase»**: она подписывает JWT, меняет его на токен и отвечает либо «Связь есть» с
именем проекта, либо текстом отказа от Google. Это самый быстрый способ отделить
«сервер не может добыть токен» от всех прочих причин, по которым пуш может не дойти.

## 4. Включить канал

**Управление персоналом → Настройка → Каналы уведомлений**: слева список событий, справа
сверху каналы. Отметить «Пуш» у тех событий, которые должны уходить на телефон. Пока не
отмечено ни одного, строки доставки не создаются вовсе — журнал в приложении работает, а
пуша нет.

Там же снизу — «Кому не отправлять выбранное событие»: персональное отключение, чтобы
человеку, которому «Просрочена» приходит по сотне в день, было что выключить кроме всего
сразу.

## 5. Регламентное задание — без него не уйдёт ничего

Отправка идёт не в сессии бизнес-операции (иначе сбой FCM откатывал бы назначение задачи),
а отдельным заданием. Его надо завести: **Администрирование → Scheduler → Задания**.

| Действие | Период | Зачем |
|---|---|---|
| `StoreTask.processDeliveries` | **10–15 секунд** | отправляет накопившиеся строки доставки |
| `StoreTask.processNotifications` | раз в сутки, после полуночи | создаёт «срок завтра» и «просрочено» |

Период первого задания — и есть та задержка, которую человек воспримет как «пуш пришёл не
сразу». Тик вхолостую стоит одного запроса к базе, экономить тут не на чем.

## 6. iOS: APNs-ключ

Пуш на iPhone идёт не напрямую, а через APNs, и Firebase должен уметь туда ходить. Нужен
**платный Apple Developer Program** (99 $/год) — без него шаг не проходится, бесплатный
аккаунт пушей не даёт.

1. [developer.apple.com](https://developer.apple.com/account) → Certificates, Identifiers &
   Profiles → **Keys** → создать ключ с галочкой **Apple Push Notifications service (APNs)**.
   Скачивается `.p8` — **ровно один раз**, второй раз его не скачать; потеряется — только
   создавать новый.
2. Записать **Key ID** (в карточке ключа) и **Team ID** (правый верхний угол консоли).
3. Firebase → «Настройки проекта → **Cloud Messaging**» → раздел iOS → загрузить `.p8`,
   ввести Key ID и Team ID.
4. В Xcode: target Runner → **Signing & Capabilities** → добавить **Push Notifications**.
   `UIBackgroundModes` с `remote-notification` уже прописан в `Info.plist`, так что
   Background Modes покажется включённым. Entitlements Xcode заведёт сам — руками файл
   создавать не надо, иначе он разъедется с проектом.

## Проверка

Android проверяется на эмуляторе, но **образ должен быть с Google Play** (в Android Studio
такие помечены «Google Play», а не «Google APIs»): без сервисов Google FCM на устройстве
не работает вовсе, и приложение молча не получит токен.

Порядок:

1. Войти в приложение. Разрешить уведомления, когда система спросит (на Android 13+ и на
   iOS диалог обязателен — без него не покажется ничего).
2. Убедиться, что телефон появился в **Операции → Устройства для уведомлений**: там видно,
   за кем он числится, платформа, версия сборки и время последнего контакта. Не появился —
   дальше идти незачем, разбираться надо здесь.
3. С другого аккаунта назначить этому человеку задачу.
4. **Свернуть приложение или закрыть его совсем** — это и есть предмет задачи, на открытом
   приложении уведомление и без пуша приезжает опросом за минуту.
5. Уведомление приходит в шторку; нажатие открывает нужную задачу.

Если не пришло — смотреть в **Операции → Уведомления**, фильтр «Не доставлено» (F9): в
строке доставки лежат канал, число попыток и текст ошибки от Google целиком.

Отдельно: серверу нужен исходящий доступ к `oauth2.googleapis.com` и `fcm.googleapis.com`.
На стенде за корпоративным прокси это первое, что стоит проверить кнопкой из шага 3.

## Выход из аккаунта

Проверить отдельно, это мина безопасности: токен привязан к паре «устройство плюс
пользователь», и уведомления следующего сотрудника не должны уехать на телефон
предыдущего. Выйти из аккаунта, убедиться, что строка пропала из «Устройства для
уведомлений», войти другим человеком — строка должна появиться снова, уже за ним.
