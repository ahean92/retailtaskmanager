MVP. Задачи для магазинов (полевые задачи и проверки по чек-листам)


Общая идея

  Проверяющему/сотруднику падает ЗАДАЧА по торговому объекту (магазину).
  Задачи бывают разных ТИПОВ: проверка по чек-листу, пересчёт остатков товара,
  проверка ценников и др. Тип определяет наполнение задачи и способ её выполнения.

  Объект проверки — АБСТРАКТНЫЙ (сейчас магазин = Location); логика подключается
  сбоку, ядро задач не зависит ни от конкретного типа объекта, ни от типа задачи.
  Новый тип задачи добавляется как плагин, не трогая ядро.

  Первым реализуем эталонный тип — «Проверка по чек-листу».


1. Каркас задач (типонезависимое ядро)

Сущности:
  Тип задачи — вид работы: проверка по чек-листу, пересчёт остатков, проверка ценников…
    Определяет, чем наполняется задача и как проверяющий её выполняет. (паттерн: TaskType)
  Объект проверки — АБСТРАКТНЫЙ: имя, (опц.) адрес, ответственный.
    Реализация №1 — Location (магазин), подключается тонким расширением сбоку.
  Задача (наряд) — объект, тип, назначена на (проверяющий), срок, приоритет, статус, автор.
    Тип-специфичное наполнение добавляется подтипом.
  Выполнение (результат) — одна попытка выполнения задачи: дата/время, фактический
    исполнитель, статус, итог. Одна задача → несколько выполнений (перепроверки, 1:N).
    Тип-специфичные детали — внутри выполнения.

Процессы:
  Создать задачу — выбрать объект, тип, назначить проверяющего, задать срок.
  Назначить / переназначить — сменить исполнителя.
  Начать выполнение — из задачи создаётся Выполнение, задача → «в работе».
  Завершить выполнение — итог фиксируется, задача → «выполнена».
  Перепроверить — новое Выполнение по той же задаче; актуальный итог = последнее.
  Найти / отфильтровать — по объекту, типу, исполнителю, статусу, сроку.

Формы:
  Список задач — таблица с фильтрами (мои, по объекту, по типу, просроченные).
    (поиск, фильтр, создание, назначение)
  Карточка задачи — общая шапка + область типа (наполнение) + история выполнений.
    (создание, правка, запуск выполнения)
  Мои задачи — что назначено на меня и что просрочено.
    (рабочий стол проверяющего)

Что отложили:
  План-график / периодичность (авто-создание задач), маршруты проверяющего,
  офлайн-мобильный режим, эскалации.


2. Конструктор чек-листов (определение типа «проверка по чек-листу»)

Сущности:
  Чек-лист (шаблон) — название, вид, активен/архив, метод итога
    (сумма баллов / % от максимума / средневзвешенное), проходной порог.
  Раздел — блок пунктов внутри чек-листа: название, порядок, вес.
  Пункт — формулировка, порядок, вес, критичность (провал = провал всего листа),
    требовать фото/комментарий при несоответствии, подсказка-норматив. Ссылается на шкалу.
  Шкала оценки — переиспользуемый справочник способов ответа
    (Да/Нет, Светофор, 0–5, числовая с нормой).
  Вариант шкалы — подпись, балл, порядок, флаги «несоответствие» и «не применимо».
  Локальные варианты пункта — необязательное переопределение вариантов у конкретного
    пункта (флаг «свои варианты» перекрывает справочную шкалу).

Процессы:
  Собрать чек-лист — разделы → пункты, каждому пункту выбрать шкалу и вес.
  Переопределить варианты у пункта — включить «свои варианты» вместо справочной шкалы.
  Отметить критичные пункты — их провал валит весь лист независимо от процента.
  Архивировать — чек-лист / пункт не удаляем, а архивируем (бережём историю проверок).
  Клонировать — новый чек-лист на базе существующего.

Формы:
  Справочник шкал — шкалы и их варианты с баллами.
    (настройка способов ответа)
  Список чек-листов — фильтр активные/архив, кнопки: добавить, клонировать.
    (поиск, создание)
  Конструктор чек-листа — дерево Разделы → Пункты, редактирование пунктов и выбор шкал.
    (сборка шаблона)

Что отложили:
  Версионирование шаблонов (снимок структуры в проверку), библиотека готовых чек-листов,
  условные пункты (показывать пункт в зависимости от ответа на другой).


3. Проведение проверки по чек-листу (исполнение типа)

Сущности:
  Проверка — Выполнение типа «чек-лист»: наследует объект и чек-лист из задачи,
    фактический проверяющий, дата/время, статус (идёт / завершена), итог, вердикт.
  Ответ на пункт — значение (вариант шкалы / число), полученный балл, комментарий,
    фото, флаг несоответствия (выводится из варианта или нормы).
  Оценка — вычисляемая: баллы / максимум / % по разделам и по листу, вердикт «пройдено/нет».

Процессы:
  Начать проверку — из задачи, подтягивается структура чек-листа.
  Заполнить — по каждому пункту выбрать вариант / ввести число; при несоответствии —
    комментарий и фото (если требуется пунктом).
  Посчитать оценку — баллы по разделам и итог считаются на лету;
    критичный провал → «не пройдено» независимо от процента.
  Завершить — итог фиксируется снимком, задача → «выполнена».
  Перепроверить — новая проверка по той же задаче; актуальный итог = последняя проверка.

Формы:
  Бланк проверки — разделы и пункты, поля ответа, фото/комментарий, счётчик оценки.
    (заполнение в поле)
  Карточка проверки (просмотр) — итог, разбивка по разделам, список несоответствий.
    (разбор результата)
  Список проверок — по объекту / периоду / вердикту.
    (история и сравнение)

Что отложили:
  Электронная подпись проверки, оспаривание результата, автосоздание задач на устранение
  из проваленных пунктов (см. блок 4).


4. Другие типы задач (расширение каркаса)

  Каждый новый тип добавляет своё наполнение к Задаче и свои детали к Выполнению —
  через подтип / абстрактные хуки, не трогая ядро. Эскизно:

  Пересчёт остатков товара:
    наполнение задачи — перечень товаров (или «весь объект»);
    выполнение — фактическое количество по товару, расхождение с учётной системой.
  Проверка ценников:
    наполнение задачи — товары / ценники к проверке;
    выполнение — цена на полке vs системная, отметка соответствия, фото.

Что отложили:
  Несоответствие → корректирующее действие (задача магазину «устранить», срок, перепроверка),
  рейтинг и динамика оценок объектов, интеграция пересчёта с учётом остатков,
  интеграция ценников с прайс-листом.
