## Тема

**[#37456](http://support.luxsoft.by/issues/37456) [Задачи] Корректирующие действия: вкладка на карточке задачи и плитка/вердикт в просмотре выполнения** — оценка S–M.

## Проблема

Корректирующие задачи сегодня видны только на форме бланка (`EXTEND FORM filling`,
блок «Корректирующие задачи»). С карточки задачи-проверки пути к ним нет вовсе:
вкладка «Выполнения» открывает HTML-просмотр выполнения (`executionCard`), а из него
ни к бланку, ни к корректирующим не перейти. Обратный переход есть (из корректирующей
— «Исходная проверка»), прямого — нет.

Кроме того, просмотр выполнения не отвечает на главный вопрос «что сделали с найденным»:

- плитки фактов (`factsHtml`) показывают «Отвечено / Замечаний / Исход», но не
  корректирующие;
- вердикт (`scoreHtml`) рисуется только у бланков с баллами (`IF hasScored(e)`) —
  у чек-листов без оценок (весь демо-шаблон «Демо КА: экспресс-проверка зала»,
  «Стандарты магазина») карточка остаётся вовсе без вердикта, хотя `nameVerdict`
  осмыслен всегда.

## Часть 1. Вкладка «Корректирующие» на карточке задачи

Модуль: `corrective/Corrective.lsf` (владелец данных), колонки перепроверки — из
`corrective/CorrectiveRecheck.lsf`.

- Новая вкладка в таб-контейнере `details` карточки `task` (объявлен в
  `StoreTaskForms.lsf`, `tabbed = TRUE`), после вкладки «Выполнения»
  (`executionsTab`, собирается в `task/Execution.lsf`): `EXTEND FORM task` с группой
  объектов + `DESIGN task { details { NEW correctiveTab { … } } }`.
- Грид — те же колонки, что на форме бланка: `id`, `nameSourceField`, `name`,
  `nameAssignedTo`, `nameStatus`, `deadline`, `resolved`, `resolvedDate` + колонки
  перепроверки `recheckDate`, `recheckFailed`; кнопки `openSimpleExecution`
  (TOOLBAR) и `openSourceFilling`.
- Фильтр: `task(sourceFilling(ct)) = t AND isCorrective(ct)` — корректирующие,
  рождённые выполнениями этой задачи.
- Пустая вкладка у задач без корректирующих — норма: прецедент уже есть, вкладка
  «Выполнения» точно так же пустует у большинства задач.
- Мобильная карточка (PulseForm) собирает всё в один таб-контейнер (`DESIGN task`
  переносит `header` и `comments` в `details`) — новая вкладка подхватится сама,
  PulseForm не трогаем. Проверить на стенде скриншотом.
- Блок «Корректирующее действие» в шапке у САМИХ корректирующих задач остаётся как
  есть — это их собственная карточка, дублировать не нужно.

## Часть 2. Карточка выполнения (`home/ExecutionView.lsf`)

- `factsHtml(Filling)` += плитка «Корректирующих: N» (`factHtml` + `countCorrective`,
  оба уже есть) **по `finished(e)`**: у завершённой проверки «0» — тоже честный ответ
  («создавать не стали»), у черновика плитка не шумит. CSS не нужен — класс
  `pulse-exec-fact` существует.
- `scoreHtml(Filling)` += ветка для завершённых бланков без баллов:
  `IF NOT hasScored(e) AND finished(e)` — простая ok/bad-плашка
  («Пройдено»/«Не пройдено» по `passed(e)`, классы `pulse-exec-score-ok/bad`)
  **без процента** — у бланка без баллов его и нет.
- В `REQUIRE` ExecutionView добавить `Corrective` — цикла нет: Corrective про
  ExecutionView не знает. Альтернатива (если хочется обратного направления
  зависимостей) — реализацию плитки держать в Corrective, расширяя ABSTRACT
  `factsHtml`, но тогда REQUIRE Corrective → ExecutionView; выбрать одно из двух
  на месте.

## Принятая семантика вердикта (зафиксировать, чтобы не переспрашивать)

У бланка без шкалы `passed` считается по критичным провалам и порогу, а не по обычным
несоответствиям, поэтому вердикт «Пройдено» стоит даже при наличии замечаний.
Проверено на стенде (2026-10-02): у демо-заполнения с двумя несоответствиями
`nameVerdict = «Пройдено»`. Это не новая проблема — та же подпись уже на телефоне
(`FillReadApi.verdict`) и в `resultSummary` (уведомления, журнал попыток). Рядом будет
плитка «Замечаний: N», так что картина честная. В тикете НЕ считать это дефектом.

## Критерии приёмки

1. У задачи-проверки с корректирующими вкладка показывает их список со всеми
   колонками и кнопками; сортировка по сроку, как на форме бланка.
2. У задачи без корректирующих вкладка пуста; у самих корректирующих задач шапочный
   блок не изменился.
3. Мобильная карточка: вкладка видна в общем списке вкладок, грид читается.
4. `executionCard` завершённой проверки с корректирующими: плитка «Корректирующих: N»
   и вердикт; без корректирующих — «Корректирующих: 0»; у бланка со шкалой —
   как было (процент + вердикт); у фотоотчёта (`SimpleExecution`) плитки нет.
5. `get_file_problems` на изменённых файлах чисто (с оговорками AGENTS.md), служба
   стартует успешно.
