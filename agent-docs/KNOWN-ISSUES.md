# Известный шум инструментов (не чинить по нему код)

Реестр ложных срабатываний и граблей каналов диагностики — чтобы не
пере-диагностировать одну и ту же странность в каждой сессии. Операционные
правила запуска сервера, стенда и тестов — в [../AGENTS.md](../AGENTS.md);
здесь только то, что **выглядит как ошибка, но ею не является**, и то, что
выглядит как чья-то ошибка, а является свойством канала.

| Симптом | Причина | Что делать |
|---|---|---|
| `get_file_problems`: `'LOCAL' unexpected` на строке `LOCAL fails = STRING();` в `scripts/tests/*_check.lsf` | IDE парсит файл как модуль, где верхнеуровневый `LOCAL` невалиден; `/eval/action` исполняет текст как тело действия, где он корректен | Ложный positive, не чинить; на eval-скриптах доверять остальным диагностика |
| `get_file_problems` оборвался по таймауту | Канал MCP (см. AGENTS.md «Таймауты») | Обрыв ≠ чистота: повторить после прогрева (поиск/чтение через IDE); для больших файлов — снимок проблем до правки, считать только новые |
| `lsfusion_find_elements` возвращает дубли | В индекс попадают копии исходников из `.claude/worktrees` | Дедуплицировать по имени и модулю |
| Сервер: «not found» у элемента, который в `src` заведомо есть | Сервер грузит `target/classes`; после `rename_refactoring` или массовых правок одиночный хук-синк не покрывает всё | Полная синхронизация: `cp -r src/main/lsfusion/. target/classes/ && cp -r src/main/resources/. target/classes/` |
| `get_file_problems`: `Can't resolve property wrap` в DESIGN-блоках (`PROPERTY(...) { wrap = TRUE; wrapWordBreak = TRUE; }`) | Плагин не резолвит design-опции компонент (наблюдение 2026-10-02, `HypothesisForms.lsf`); код при этом компилируется и стартует | Не «чинить» design-опции по инспекции; критерий — запуск службы |
| Веб-клиент рисует пустой экран после рестарта сервера | Tomcat держит RMI-заглушки старого инстанса | Перезапустить `.lsfusion-dev/cemetery-demo/run-web.ps1` |
| FLOAT-модалки (`SHOW … WAIT`, `DIALOG`) молча не открываются в веб-клиенте, асинхронные вкладки работают | `webSocket.port` занят (erp-стенд держит 8887) | Серверу задавать `-DwebSocket.port=8888` |
| `ClassNotFoundException: …BusinessLogicsBootstrap` при запуске из Git Bash | Git Bash портит `-cp` с `;` | Префикс `MSYS_NO_PATHCONV=1` |

## Хук синхронизации

PostToolUse-хук (`scripts/sync-lsf-to-target.ps1`, матчер в `.zcode/config.json`)
копирует правку в `target/classes` автоматически для встроенных `Edit|Write` и
IDE-инструментов `replace_text_in_file` / `create_new_file` /
`lsfusion_set_meta_visibility`.

- Не покрывается `rename_refactoring` (несколько файлов за раз, в событии нет
  одного пути) — после переименований полная синхронизация вручную (см. таблицу).
- Изменения конфига хука применяются после рестарта сессии ZCode.
